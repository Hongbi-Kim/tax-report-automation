**질문하며 배운 것**: 담당자는 정해진 내용만 답하고 나머지는 “확인해보고 말씀드릴게요”라고 답한다. 파일은 요청해야 받는다(2차 재송부). 기술 용어 대신 ‘어느 서식 몇 쪽의 어떤 칸이 어떻게 보이고, 그래서 보고서의 무엇을 못 쓰는지’를 적어야 답이 온다. 답이 모호한 단어를 포함하면(예: ‘고정’) 바로 «답변 있음»으로 분류하지 말고 해석을 적어 둔다.

## 1. 상태 정의

| 상태 | 뜻 | 프로그램 처리 |
|---|---|---|
| **답변 있음** | 답이 명확하고 다른 자료와 충돌하지 않음 | 답 내용을 규칙/값으로 반영, 관련 값 «확정» |
| **불명확·충돌** | 답이 모호하거나, 문서 또는 이전 답과 맞지 않음 | 관련 값 «확인 필요» 유지, 후속 질문 생성 |
| **답변 없음** | 아직 묻지 않았거나 답을 받지 못함 | 가정이 있으면 «가정», 없으면 «확인 필요» |

## 2. 질문 하나에 남기는 항목

모든 질문은 아래 4개 항목을 반드시 가진다.

| 항목 | 내용 |
|---|---|
| **질문** | 담당자에게 보내는 문장 그대로 |
| **필요한 이유** | 답이 없으면 무엇을 만들 수 없는지 |
| **관련 파일·페이지** | 질문의 근거가 된 파일, 서식, 페이지(또는 엑셀 셀) |
| **답에 따라 달라지는 구현** | 답 별로 코드·설정·출력이 어떻게 바뀌는지 |

여기에 상태, 답변 기록, 답을 받기 전까지 쓰는 가정, 후속 질문을 덧붙인다.

### 기록 형식 (`config/questions.yaml`)

```yaml
- id: Q-001
  topic: 보고서 목차
  question: "..."                  # 질문
  why: "..."                       # 필요한 이유
  refs:                            # 관련 파일·페이지
    - {file: 법인세보고서_출력예시.xlsx, loc: "B6~B118"}
    - {file: 샘플세무법인_요구사항.xlsx, loc: "C9~C16"}
  impl_by_answer:                  # 답에 따라 달라지는 구현
    - {if: "1안", then: "..."}
    - {if: "2안", then: "..."}
  assumption: A-001
  status: 답변 있음
  answers:
    - at: 2026-11-21
      by: 담당자
      text: "..."
      classified_as: 답변 있음
      note: "..."
  follow_up: [Q-011]
```

## 5. 질문 상세

### Q-001 보고서 목차 — **답변 있음**

**질문**
> 법인세 분석 보고서의 목차(들어갈 항목과 순서)는 어느 쪽을 기준으로 할까요?

| 부가세 별도 | 청구서에 공급가액·부가세·합계 3줄 |
| 3~5번 규칙 추가 | 할인·최저보수 등 규칙을 계산 파이프라인에 추가 |
