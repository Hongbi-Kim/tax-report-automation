# 02. 데이터 모델과 근거 추적

## 1. 기본 원칙

보고서에 들어가는 모든 숫자·문장은 `Value` 객체를 거친다. 근거 없는 값은 만들 수 없게 모델에서 강제한다.

## 2. Evidence (근거)

```python
class Evidence(BaseModel):
    file: str          # "샘플컴퍼니_2025_세무조정계산서.pdf"
    form: str          # "손익계산서" / "법인세과세표준및세액조정계산서(별지3)"
    page: int          # PDF 실제 쪽 번호(1부터)
    item: str          # "Ⅰ.매출액" / "코드 07 이월결손금"
    column: str | None # "제2(당)기" / "제1(전)기" / "기초액"
    raw_text: str      # PDF에서 읽은 원문 그대로 "Ⅰ. 매 출 액 192,734,983 92,944,479"
    bbox: tuple[float, float, float, float] | None  # 글자 좌표(검수 화면에서 강조용)
```

## 3. Value (값)

```python
class Status(str, Enum):
    CONFIRMED = "확정"        # 문서에서 직접 읽었고 대사 통과
    DERIVED   = "계산"        # 확정값만으로 계산
    ASSUMED   = "가정"        # 담당자 답이 없어 가정을 적용
    NEEDS_CHECK = "확인 필요"  # 값을 정할 수 없음 → 출력 안 함
    CONFLICT  = "충돌"        # 근거끼리 값이 다름

class Value(BaseModel):
    key: str                  # "is.revenue.2025"
    label: str                # "매출액"
    amount: Decimal | None
    text: str | None          # 코멘트 문장일 때
    status: Status
    evidence: list[Evidence]  # CONFIRMED/CONFLICT 는 1개 이상 필수
    inputs: list[str] = []    # DERIVED 일 때 사용한 Value key 목록
    formula: str | None       # "부채총계 / 자본총계 × 100"
    assumption: str | None    # ASSUMED 일 때 가정 내용
    question_ids: list[str]   # 연결된 질문(Q-001 …)
```

### 상태 결정 규칙

| 조건 | 상태 |
|---|---|
| 한 서식에서 읽음 + 다른 서식과 일치(또는 비교 대상 없음) | 확정 |
| 두 근거가 다름 | 충돌 (두 근거 모두 저장) |
| 입력이 모두 확정/계산 | 계산 |
| 입력에 가정이 하나라도 있음 | 가정 (상태가 전파됨) |
| 입력에 충돌·확인 필요가 하나라도 있음 | 확인 필요 |
| 연결된 질문이 «답변 있음» → 답 내용으로 값 확정 | 확정(근거에 “담당자 답변 Q-xxx, 날짜” 추가) |

## 4. 출력 표시 규칙

| 상태 | 보고서(PDF/Excel) 표시 |
|---|---|
| 확정 | 값 그대로 |
| 계산 | 값 그대로 (근거 대장에 계산식) |
| 가정 | 값 + `ᴬ` 표시, 하단 “가정 사항” 목록에 내용과 Q-ID |
| 확인 필요 | 값 자리에 **«확인 필요»**, 하단에 사유와 Q-ID |
| 충돌 | 값 자리에 **«확인 필요»** + 두 근거 값을 각주로 표시 |

Excel에서는 상태별 셀 색을 다르게 하고(가정: 노랑, 확인 필요: 빨강 테두리), 셀 메모에 근거를 넣는다.

| 보고서 위치 | 항목 | 값 | 상태 | 파일 | 서식 | 페이지 | 항목/열 | 원문 | 계산식 | 질문 |

## 6. 코멘트 문장의 근거

요약 코멘트(요구사항 3번)는 문장을 템플릿으로 만들고, 문장 안의 숫자마다 Value key를 연결한다. 확정·계산값만 들어간 문장은 그대로 출력하고, 가정·확인 필요 값이 들어가면 문장 끝에 표시를 붙인다. **AI가 자유롭게 문장을 지어내지 않게 한다**(숫자를 바꾸거나 없는 사실을 만드는 위험 차단).


## 7. 최종 보완 (2~4차)

### 7.1 Evidence 추가 필드
- `bbox` — 값이 있던 칸의 좌표(x0, x1, top, bottom). 경고 캡처와 체크 표시 판독 근거에 사용.

### 7.2 Value 플래그 (`flag`) — «확인 필요»의 이유
| 플래그 | 뜻 | 판단 |
|---|---|---|
| `가림` | 회색 처리된 칸(아래 숫자 텍스트 없음) | PDF에 실제로 보이는 내용 |
| `글자표기` | 금액 칸에 숫자 대신 글자(예: 확인중) | PDF에 실제로 보이는 내용 |
| `합계빈칸` | 합계 칸이 빈칸인데 하위 항목이 가림·글자 | PDF에 실제로 보이는 내용 |
| `체크표시` | 체크 표시(○)를 판독하지 못함 | 추출 한계 |
| `서식없음` | 해당 서식이 PDF에 없음 | 자료 부족 |
| `추출실패` | 서식은 있으나 위치를 찾지 못함 | 추출 문제 |
| `계산보류` | 입력값이 확인 필요라 계산하지 않음 | 계산 보류 |

### 7.3 키
- 전기·당기 값의 키가 겹치지 않도록 `연도:키`(예: `2024:표준손익계산서.68`)로 붙인다. 계산 보류의 원인 추적과 회귀 비교에 사용.

### 7.4 표시 규칙 추가
- 공란 칸은 계산에서 0, 표시는 「–」. 가림·글자·합계빈칸은 0으로 쓰지 않는다.
- 숫자는 PDF 텍스트로 추출되어야 한다(채점·검토 도구가 읽을 수 있게).
